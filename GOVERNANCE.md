# Governance

Ekklesia is a small project with one maintainer. This page describes how it is
run today; it will change if the project grows.

## Maintainer

**Cris Magalang** ([@crismag](https://github.com/crismag)) maintains Ekklesia.
The maintainer reviews and merges contributions, publishes releases, looks after
schema compatibility and security, and sets the project's direction.

## How contributions are made

Anyone can open an issue or a pull request; see
[CONTRIBUTING.md](CONTRIBUTING.md). Discussion happens in public issues and pull
requests, except security reports and conduct reports, which are private (see
[SECURITY.md](SECURITY.md) and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md)).

## Decisions

The maintainer decides whether a change is accepted, taking into account whether
it serves churches using Ekklesia, whether it can be maintained, and whether it
keeps existing installations working. Disagreements are worked through in the
issue or pull request; the maintainer makes the final call.

## Helping to maintain

Contributors who help regularly and carefully may be invited to review pull
requests, triage issues or help maintain parts of the project. Write access to
the repository is granted selectively and can be withdrawn.

Being able to contribute is not the same as being able to merge, release or
deploy. Merging to `main`, publishing releases and deploying to any church's
installation remain with the maintainer, or with people the maintainer has
explicitly given that responsibility.

## Releases

Releases are tagged by the maintainer, with notes describing changes, database
migrations and configuration changes. See [docs/releasing.md](docs/releasing.md).

## Paid services

Cris Magalang also offers paid deployment, configuration, data-import help and
agreed customization through [CrisHub](https://crishub.com/contact/). That work
is separate from the open project: it does not buy priority for issues or pull
requests, and the project does not require it.
