# Security policy

Ekklesia stores personal information about church members, so security reports
are taken seriously. Thank you for reporting responsibly.

## Reporting a vulnerability

**Do not open a public issue** for a suspected vulnerability.

Report it privately to the maintainer through the contact form at
<https://crishub.com/contact/>, or by email to hello@crishub.com, with "Ekklesia
security" in the subject.

When GitHub's private vulnerability reporting is enabled for this repository,
the **Report a vulnerability** button on the
[Security tab](https://github.com/crismag/Ekklesia/security) will be the
preferred channel.

## What to include

- What the problem is and what an attacker could do with it.
- Steps to reproduce, against a test installation with fictional data.
- The Ekklesia version or commit, and the installation type (web host,
  intranet, local).
- Any proof of concept, kept as small as possible.

## What not to share

- No credentials, tokens or `.env` contents, yours or anyone else's.
- No real member data. If a report needs data to make sense, describe it or
  use fictional records.
- Do not test against an installation you do not run, including Christlikeness
  Church's own; it holds real people's information.

## Supported versions

Ekklesia has no tagged releases yet. Fixes are made on `main`; once releases are
published, this section will state which ones receive security fixes.

## What happens next

The maintainer will look into the report and, where a fix is needed, prepare
one and coordinate disclosure with you. There is no guaranteed response time.
Please give reasonable time for a fix before discussing the issue publicly.
